# Held-out confirmation of the deletion protocol

The development studies motivate the directional claim that frozen deletion better preserves raw-context source-deletion responses than reranking and repacking. This protocol was written before any model scores on the held-out set. The November 14 user request authorizes this new held-out stage. The feasibility-stage data manifest remains the original provenance record.

Use all 400 questions in the pinned Hotpot official-validation subset, SHA256 `75598f99e35a5def46c440b42fc2c5168541dd751265d3d3e9f79964991cad5a`, in its original file order. The selection is question-disjoint from both project train and development splits. The underlying retrieval corpus can overlap. Run pinned Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct on the same questions. MuSiQue contributes development evidence and is outside this Hotpot confirmation.

At a cap of 512 tokens, both policies share the exact same factual selection, answer, and fixed raw-generated answer tokens used for scoring. Evaluate every singleton source deletion against the matching raw-context deletion. Frozen deletion removes the selected chunks owned by the deleted source. Reranking and repacking refits the BM25-style statistics and greedily repacks surviving input. Use the existing FP32 math attention scorer with TF32 disabled, explicit 4D causal masks, compact positions and double-precision log-softmax. The greedy raw and compressed factual answers use the existing 64-token cap. No gold support or answers enter selection or scoring.

The primary endpoint is the mean per-question absolute source-effect error. First average over sources within a question, then weight questions equally. Use the paired frozen-minus-recomputed difference and a two-sided 95% percentile interval from 5,000 question bootstrap draws, seed 20261109, with questions sorted by ID. The claim passes only if the upper interval bound is strictly below zero for each model. Otherwise report both intervals and say the cross-model criterion was unmet. The two models share questions and are reported separately. Report absolute error, pooled normalized error relative to the zero-effect predictor, top-source recovery, raw and compressed QA F1, and achieved context lengths. QA is shared between deletion policies by construction. The primary claim concerns agreement with the raw reference under the tested protocols.

A developer smoke runs two existing development questions per model. Each full job scores 50 held-out questions using fixed stride-eight shards. The review requires all eight shards per model and checks the dataset, driver hash, pinned revision, complete question coverage, shared factual tensors and targets, raw passthrough and same-shape repeatability. The smoke precedes a serial chain of sixteen single-GPU jobs, with CPU review after all outcomes. Record failures and preserve incomplete records. This is a new compute stage with a maximum reservation of 6 hours 48 minutes, based on one eight-minute smoke and sixteen 25-minute jobs. Report scheduling state separately from the result verdict.
