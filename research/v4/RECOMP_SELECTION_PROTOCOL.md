# Extractive RECOMP deletion comparison

Use the released Natural Questions extractive RECOMP checkpoint `fangyuan/nq_extractive_compressor` at revision `46f98c1f57fa919c72d86ced16e3ece3403f9e9e`. The authors list it in their [repository](https://github.com/carriex/recomp). Using their Natural Questions release avoids deliberately using the Hotpot-trained variant. Shared Wikipedia documents and pretraining exposure remain possible. Use the authors' [released scoring procedure](https://raw.githubusercontent.com/carriex/recomp/main/run_extractive_compressor.py), which ranks title-prefixed sentences by a question–sentence dot product after masked mean pooling. The paper describes CLS pooling in its model section, so record the released inference code as the implementation reference.

Evaluate all 96 existing Hotpot development questions with both pinned readers, Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct. Use the same candidate sentence segmentation, per-source framing, stable packing order and 512 reader-token cap as the BM25 frontier. This is the released RECOMP scorer under the project's provenance-preserving packing adapter. It differs from the original end-to-end RECOMP evaluation, which used its own retrieval inputs, formatting and reader. Source identity comes from the candidate index, so repeated text and titles stay distinguishable.

Each reader generates one raw target per question and uses its fixed tokens to score all singleton raw, frozen and recomputed deletions. The two compressed policies use one factual plan and answer. Frozen deletion removes selected chunks from the omitted source. The recomputed arm excludes that source's candidates and packs again. RECOMP's score for each question–sentence pair is independent of other candidates, so remaining rankings can be cached. Refilling can still replace or displace chunks. This contrasts with BM25, where recomputation also refits within-pool ranking statistics. Reuse the frontier's FP32 scorer and checks. Each question is paired within a reader and selector. The earlier BM25 frontier provides a same-question comparison of the direction and magnitude of within-selector contrasts. Any direct cross-selector pooled statistic would additionally require checking identical raw targets and numerical reference scores.

Report absolute MAE and NMAE, paired per-question frozen-minus-recomputed MAE with 5,000 question bootstrap draws, top-source recovery, actual lengths and shared factual QA. Use the existing frontier reviewer and seed. Call the development comparison consistent on both readers only if both upper interval bounds are below zero. These are development results on the same questions used to develop the paper. The separate locked BM25 confirmation provides held-out evidence for BM25.

A development smoke loads the pinned checkpoint and scores two questions per reader. Two full runs and a CPU report follow the smoke. The RECOMP chain follows the last GPU job in the held-out BM25 comparison so both studies share at most one GPU.
